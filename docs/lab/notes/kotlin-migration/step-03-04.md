## ⑤ Optional, nullable, `!!`

### Optional → nullable로 바꾼 곳

- 없음. 대상 Optional 반환부의 호출자가 아직 Java 서비스(05·06 범위)이므로 이번 단계에서 nullable 반환으로 바꾸면 범위를 침범한다.

### Optional을 유지한 곳

- `AuditLogRepository.findTopByTargetTypeAndTargetIdOrderByCreatedAtDesc`: Java 서비스 호출부 유지.
- `IdempotencyKeyRepository.findByKeyAndMemberIdAndRequestPath`: Java `IdempotencyService` 호출부 유지.
- `SpaceRankingSnapshotRepository.findMaxPeriodStart`: Java 통계 서비스 호출부 유지.

### nullable 결정

- DB nullable 컬럼과 생성 전 ID는 nullable로 유지했다.
- DB non-null 숫자 필드는 Kotlin non-null `Long`/`Int`로 유지했다. Java 호출 호환이 필요한 ID는 boxed `Long` 생성자·getter·정적 팩터리 시그니처를 별도로 유지했다.
- 응답 DTO가 영속화된 엔티티만 받는 경계의 생성 ID/생성 시각은 `requireNotNull`로 검증했다.

### `!!` 사용 위치

- 없음.

## ⑥ 리뷰 체크리스트

- [ ] HTTP 매핑·상태 코드·응답 body·쿠키/헤더 문자열이 Java 구현과 동일하다.
- [ ] 인증 필터는 JWT의 `id`, `email`, `role`을 사용하며 매 요청 회원 DB 조회를 추가하지 않았다.
- [ ] JPA 엔티티는 일반 `class`이고 Lombok 및 `data class`를 사용하지 않는다.
- [ ] DB nullable 컬럼과 Kotlin nullable 타입, non-null 컬럼과 non-null 타입이 대응한다.
- [ ] Java 생성자·getter·정적 팩터리의 boxed `Long` 및 숫자 `long`/`int` 시그니처가 유지된다.
- [ ] JPA no-arg 생성자의 public/protected 가시성과 엔티티 setter 비노출을 유지한다.
- [ ] `WaitlistEntry`의 `@DynamicUpdate`, WAITING의 `active = 1`, 취소의 `active = null`이 유지된다.
- [ ] `JdbcLoginAttemptStore`의 `REQUIRES_NEW`와 `SELECT ... FOR UPDATE`가 유지된다.
- [ ] Repository의 조건부 UPDATE 영향 행 수, `flushAutomatically`/`clearAutomatically` 속성이 유지된다.
- [ ] 통계·감사 조회 기간은 `[from,to)`이고 금액은 `Long`, 건수는 `Int`다.
- [ ] Optional은 05·06 범위 Java 호출부가 남은 세 Repository에서만 유지한다.
- [ ] 예약 30분 단위, HOLD→결제, 멱등성, 소유권, 출입 토큰 정책과 오케스트레이션 방향을 변경하지 않았다.
- [ ] Flyway·시크릿·배포 설정·테스트 파일을 변경하지 않았다.

## 검증 및 인계

- 구현: Codex.
- 검증: 별도 검증 에이전트가 범위·ABI·nullability·트랜잭션/DB 불변식을 읽기 전용으로 확인했고, 지적된 boxed `Long`, 공개 setter, no-arg 가시성을 수정한 뒤 컴파일·`javap`·직접 테스트를 재검증했다.
- 남은 한계: boxed Java getter와 Kotlin non-null 프로퍼티 접근을 함께 제공하기 위한 `get*Value(): long` 접근자가 일부 엔티티에 추가됐다. 기존 Java ABI에는 영향을 주지 않지만 실제 MySQL 저장·flush·clear·재조회는 위 통합 테스트 목록으로 확인해야 한다. 통합 테스트는 사용자 지시에 따라 실행하지 않았고, 최종 안전망은 CI와 사람(이태호)의 리뷰다.
