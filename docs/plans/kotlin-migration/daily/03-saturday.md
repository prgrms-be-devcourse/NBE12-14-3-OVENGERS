## 오늘의 목표

**요청을 받는 컨트롤러, 로그인 상태를 확인하는 필터, 서버 설정을 읽는 클래스를 옮깁니다. 같은 요청에 같은 응답이 와야 합니다.**

## 시작 전에 확인할 것

금요일 DTO와 공통 보안 코드가 합쳐졌는지 확인합니다. P0가 남아 있으면 먼저 보강하고, 그 테스트가 필요한 DB 서비스 전환은 기다립니다. 주말에 못 한 작업은 월요일에 일정을 다시 맞춥니다.

## 담당자별 할 일

| 담당 | 할 일 | 확인할 것 |
| --- | --- | --- |
| 김재철 | 공간·이미지·감사·통계의 일반/관리자 컨트롤러와 공통/이미지 설정을 옮깁니다. | 검색·페이징 기본값, 관리자 권한, 업로드 크기와 이미지 URL을 유지합니다. |
| 박창현 | 출입 컨트롤러와 인증 필터를 옮깁니다. | 비로그인/권한 없음 응답, 비활성 회원 차단, 세션 확인과 오류 JSON이 같아야 합니다. |
| 백한비 | 크레딧·중복 요청 키 관련 API 동작을 확인하고, 본인 작업 후에는 미리 정한 문의/대기열 컨트롤러를 지원합니다. | 키 누락/재사용과 권한 오류를 확인합니다. DB를 쓰는 중복 요청 서비스는 후속 일정입니다. |

| 천종원 | 로그인·인증 확인·회원·문의의 일반/관리자 컨트롤러와 메일 코드를 옮깁니다. | 리프레시 토큰 쿠키, 로그인 제한 응답, 회원/관리자 권한과 메일 설정을 유지합니다. |

## 오늘 완료했다고 말하려면

- 정상·입력 오류·비로그인·권한 없는 요청의 응답이 기존과 같고, 검색 조건·로그인 사용자·페이징 기본값이 제대로 전달되어야 합니다.
- 바꾼 설정을 서버가 읽고 계획한 실행 환경에서 시작되는지 확인합니다. 실행하지 못한 환경이나 실제 PG/메일/Kafka 연결은 따로 ‘확인 필요’로 적습니다.
- 박창현·천종원은 세션/JWT와 인증 필터를 연결해서 확인합니다.
- PR마다 [공통 안내의 전체 빌드·필요한 프론트 검사](00-overview.md)를 실행합니다.

## 다음 날 공유할 내용

일요일에는 컨트롤러/설정 PR·커밋, 서버 시작을 확인한 환경, 남은 P0를 공유합니다. DB 전환에서 null 허용 여부, 연관 데이터 읽기, 생성/수정 시각을 확인할 목록도 준비합니다.

## 구현할 때 참고

- 설정 파일 담당자는 PR 전에 정합니다. 통계 정기 실행 코드는 월요일, 예약·PG 정기 실행 코드는 화요일 서비스와 함께 옮깁니다. 오늘은 주기·시간대·빈 연결을 확인합니다.
- 대표 대상: `DoorAccessController`, `CustomAuthenticationFilter`, `TossPaymentsProperties`·PG 설정, 각 도메인 컨트롤러, 메일 인터페이스/설정/송신 코드.
- `*ControllerTest`·`*SecurityIntegrationTest`를 실행하고 MockMvc에 보안 필터를 포함했는지 기록합니다. `@CurrentMember`, `@Valid`, `@ModelAttribute`, `Pageable`, 세션 `sid`, 401/403/429·`Retry-After`·쿠키 속성을 확인합니다.
- 메일·PG·Kafka·JWT·이미지/CORS는 [실행 환경별 확인 계획](../04-mixed-build.md)을 따릅니다. 가짜 외부 서비스나 Kafka OFF 결과와 실제 연결 결과를 구분합니다.
