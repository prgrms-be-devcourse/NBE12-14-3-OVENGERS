# 2. 금요일(10/23) — API에서 주고받는 데이터 옮기기

> 기존 단계: step-2 · 앞으로 할 일을 정리한 계획입니다.
> [0. 팀 공통 안내](00-overview.md) · 이전: [1번 계획](01-thursday.md) · 다음: [3번 계획](03-saturday.md)

## 오늘의 목표

**요청·응답 데이터를 담는 DTO와 권한 확인 코드를 옮깁니다. DB·핵심 서비스 전환 전에 필요한 테스트(P0)도 마칩니다.**

## 시작 전에 확인할 것

목요일 빌드 설정과 공통 코드가 합쳐진 상태에서 시작합니다. DTO를 옮기기 전에 현재 요청·응답 예시를 확인합니다. DB를 읽고 쓰는 서비스는 필요한 P0 테스트가 끝난 뒤 옮깁니다.

## 담당자별 할 일

| 담당 | 할 일 | 확인할 것 |
| --- | --- | --- |
| 김재철 | 공간 생성/수정/검색/슬롯, 감사 조회, 통계 DTO와 공간 권한·이미지 코드를 옮깁니다. | 운영시간/가격 입력 검사, 검색 조건, 5MB 업로드 규칙과 금액의 숫자 범위를 유지합니다. |
| 박창현 | 출입 요청/응답, 출입 권한, 로그인 사용자 정보·JWT 코드를 옮깁니다. | 빈 토큰 등 잘못된 입력을 거절하고 Java 호출부도 계속 동작해야 합니다. 인증 연결은 천종원과 확인합니다. |
| 백한비 | 예약 상태 이력 응답, 크레딧 인터페이스, 중복 요청 키를 읽는 코드를 옮기고 금전 테스트를 보강합니다. | 같은 키의 재요청, 다른 내용으로 키 재사용, 잔액 초과 동시 차감, 환불/위약금 기록을 확인합니다. |
| 이태호 | 예약·충전·PG·웹훅·대기열·알림 DTO와 DB를 직접 사용하지 않는 연결 코드를 옮깁니다. | JSON 필드·날짜·금액·상태값과 기존 메시지 데이터 형식이 같아야 합니다. |
| 천종원 | 인증·회원·문의 DTO와 권한 확인 코드를 옮기고 문의/인증 테스트를 보강합니다. | 본인 데이터만 접근하고 빈 값/누락/null을 기존처럼 처리해야 합니다. 토큰 재사용·세션 폐기·관리자 상세도 확인합니다. |

## 오늘 완료했다고 말하려면

- 정상 요청의 응답과 입력 오류·권한 없는 요청의 거절 방식이 기존과 같아야 합니다.
- Java에서 DTO를 부르는 부분이 빌드되고 프론트 테스트·타입 검사가 통과해야 합니다.
- [P0 테스트 목록](../01-test-baseline.md)에 실행 결과와 남은 보강을 적습니다. DB 저장/되돌리기는 Mock 테스트만으로 완료 처리하지 않습니다. P0가 남으면 관련 DB·핵심 서비스 전환은 기다립니다.
- PR마다 [공통 안내의 전체 빌드·필요한 프론트 검사](00-overview.md)를 실행합니다.

## 다음 날 공유할 내용

토요일에는 DTO PR/커밋, 남은 DTO, P0 결과, 컨트롤러·보안·설정에서 함께 고칠 부분을 공유합니다. 지원할 경우 문의 또는 대기열/알림 중 맡을 파일을 먼저 정합니다.

## 구현할 때 참고

- 대표 대상: `SpaceAuthorizationService`, `DoorAccessAuthorizationService`, `AuthPrincipal`, `CurrentMember`와 resolver/JWT 유틸, `ReservationStatusHistoryResponse`, `CreditService`, `IdempotencyKeyHeaderResolver` 및 각 도메인 DTO.
- DB를 사용하는 `IdempotencyKey`·Repository·`IdempotencyService`는 일~월요일에, 설정 클래스 전환은 토요일에 진행합니다.
- `@AssertTrue`, `@ModelAttribute`, JSON 누락/null, 검증 애너테이션 위치(`@field:`, `@get:`, `@param:`)와 기존 Int/Long 범위를 확인합니다.
- DTO의 `data class`·`@JvmRecord`는 [기존 결정](../../../decisions/kotlin-data-class-scope.md)을 따릅니다. Java record 접근자·Lombok 메서드를 사용하는 호출부도 같은 PR에서 맞춥니다.
- 관련 Controller/Service 테스트로 정상·입력 오류·권한 오류를 확인한 뒤 전체 빌드·프론트 검사를 실행합니다.
