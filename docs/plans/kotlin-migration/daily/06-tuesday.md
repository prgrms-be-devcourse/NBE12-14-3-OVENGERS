# 6. 화요일(10/27) — 핵심 기능 옮기고 전체 흐름 확인하기

> 기존 단계: step-5 → 조건 충족 시 step-6 · 앞으로 할 일을 정리한 계획입니다.
> [0. 팀 공통 안내](00-overview.md) · 이전: [5번 계획](05-monday.md)

## 오늘의 목표

**돈·예약·로그인·출입 상태를 직접 바꾸는 핵심 코드를 옮기고 전체 기능을 다시 확인합니다. 오늘 완료가 목표이며 필요한 작업은 수요일(10/28)에 이어서 합니다.**

## 시작 전에 확인할 것

공통 엔티티·P0·이벤트 처리 확인이 끝난 기능부터 시작합니다. 오전에 함께 쓰는 엔티티·인터페이스와 DB 잠금 순서를 맞추고 각 PR에서 옮길 파일을 정합니다. 선행 실패가 있으면 관련 전환은 기다립니다.

## 오늘 완료했다고 말하려면

- 실제 DB의 잔액·내역·예약 상태·슬롯·토큰·이벤트를 다시 읽어 확인합니다. 취소/연장/HOLD와 탈퇴 경합, PG 확정/복구/웹훅 중복, 토큰 재사용·비활성 출입을 포함합니다.
- 동시 요청 테스트는 실제로 잠금을 기다리는 지점과 순서를 확인하고 시간 제한을 둡니다. 두 요청을 동시에 시작한 것만으로 잠금 검증을 마쳤다고 보지 않습니다.
- 각 PR과 최종 합친 커밋에서 전체 빌드를 실행하고 실제 테스트 수·실패/오류/스킵을 남깁니다. 과거 1,048건 통과는 비교 자료입니다.
- PR마다 [공통 안내의 전체 빌드·필요한 프론트 검사](00-overview.md)를 실행합니다.

## 핵심 전환을 마친 뒤 할 일

- 남은 Java·Lombok 사용을 정리하고 남길 파일은 이유를 적습니다. 아직 Java에서 쓰는 설정은 유지하고 정리 PR도 확인합니다.
- Flyway 전체 목록/체크섬을 확인하고, 계획된 실행 환경에서 JAR로 서버가 시작되는지 봅니다. JAR 생성과 실제 기동·정상 HTTP 응답은 구분합니다.
- **로그인 → 충전 → 예약 결제 → 출입 → 취소 → 대기열/알림**, 통계 조회/확정을 이어서 확인합니다. 가짜 PG/메일과 실제 PG·SMTP·Kafka 연결 여부를 기록합니다.
- 프론트 테스트·타입 검사, 프론트 수정 시 lint/build를 실행합니다. CI 빌드와 `DEPLOY_ENABLED` 조건에 따른 실제 배포도 구분합니다.
- `docs/testing/test-results.md`와 작업별 결과/리뷰에 날짜·커밋을 남기고 관련 문서도 실제 코드에 맞춥니다. 핵심 전환·정리·필수 점검이 끝나고 공통 완료 기준을 충족해야 전체 완료입니다.

## 다음 날 공유할 내용

끝난 범위는 결과로 남깁니다. 미전환 코드·실패한 테스트·필수 확인이 남으면 완료 처리하지 않고 수요일 할 일, 담당, 커밋, 실패 내용, 완료 조건을 정합니다. 일정 때문에 테스트나 완료 기준을 줄이지 않습니다.

## 구현할 때 참고

- 정확한 파일은 [기존 팀원별 상세 계획의 step-5](../team-guide.md)를 봅니다. 예약·PG·인증은 작은 PR로 나눕니다. 함께 바꿔야 빌드되는 엔티티·저장소·Java 호출부는 같은 묶음으로 다룹니다.
- 공간: `Space`·Repository·서비스, `version: Int = 0`의 수동 증가·결제 시 비교와 기존 비관적 잠금을 유지합니다. 현재 없는 JPA `@Version`은 추가하지 않습니다. 출입: `DoorAccessToken`, `DoorAccessLog`·Repository·서비스, 비활성 기록 `REQUIRES_NEW`.
- 크레딧: `CreditTransaction`·Repository·서비스, 잔액 조건부 UPDATE 영향 행과 금액 상한/부호. 예약/PG: `Reservation`, `ReservationSlot`, `ChargeOrder`·Repository·서비스/배치, 공간/예약/회원 잠금 순서·슬롯 UNIQUE·TOP_UP 1회·PG 호출과 DB 확정의 별도 빈.
- 인증/회원: `Member`, `LocalCredential`, `AuthSession`, `RefreshToken`, 인증 증표/guard·Repository·서비스. MapsId/LAZY·증표 MANDATORY·재사용 시 세션 폐기·동반 롤백을 확인합니다.
- 기존 동등성·null·숫자 범위·주입 `Clock`·트랜잭션 설정을 유지합니다. 직접 건 잠금뿐 아니라 관련 FK/UPDATE의 순서도 확인합니다.
