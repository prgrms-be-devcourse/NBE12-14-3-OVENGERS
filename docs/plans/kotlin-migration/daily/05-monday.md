# 5. 월요일(10/26) — 알림·대기열·통계가 이어서 동작하는지 확인하기

> 기존 단계: step-4 후반 · 앞으로 할 일을 정리한 계획입니다.
> [0. 팀 공통 안내](00-overview.md) · 이전: [4번 계획](04-sunday.md) · 다음: [6번 계획](06-tuesday.md)

## 오늘의 목표

**DB 저장 코드를 사용하는 서비스와 이벤트 처리를 옮깁니다. 예를 들어 예약 취소로 자리가 풀리면 이벤트가 기록되고 알림이 중복 없이 전달되어야 합니다.**

## 시작 전에 확인할 것

주말에 실제로 끝난 일과 남은 일을 모읍니다. 해당 P0와 엔티티 전환 결과가 있어야 이를 사용하는 서비스를 옮깁니다. 못 한 일이 많으면 화요일에 끝낼 범위와 수요일로 넘길 범위를 다시 정합니다.

## 담당자별 할 일

| 담당 | 할 일 | 확인할 것 |
| --- | --- | --- |
| 김재철 | 감사 기록 서비스와 통계 조회·확정·보충·정기 실행 코드를 옮깁니다. | 감사 기록이 원래 작업과 함께 저장되고 통계 확정 시각·재계산 결과가 같아야 합니다. |
| 박창현 | 로그인 세션·인증 필터·비활성 회원 출입을 연결해 확인하고 맡은 알림/대기열 지원을 마칩니다. | 폐기된 세션·권한 없는 요청을 기존처럼 거절해야 합니다. 화요일 출입 시간/상태 테스트를 준비합니다. |

## 오늘 완료했다고 말하려면

- 취소/만료 처리가 실패하면 함께 저장하던 이벤트도 남지 않아야 합니다. 이벤트 수신 처리가 실패하면 처리 완료 기록과 알림 저장도 함께 되돌아가야 합니다.
- 기존에 저장한 이벤트를 새 코드가 읽을 수 있어야 합니다. 대기열 동시 수정, 알림 읽음, 통계 확정/재확정도 확인합니다.
- Kafka를 끈 테스트, 켠 설정, 실제 브로커 송수신 결과를 구분합니다. 개별 PR과 합쳐진 브랜치의 테스트 결과도 구분합니다.
- PR마다 [공통 안내의 전체 빌드·필요한 프론트 검사](00-overview.md)를 실행합니다.

## 다음 날 공유할 내용

목~월에 남은 파일·테스트, 핵심 코드 담당 파일·PR 순서를 정해 화요일에 공유합니다. 공간·회원·잔액·예약·출입 담당자끼리 공유 인터페이스와 DB 잠금 순서를 맞춥니다. 선행 실패는 먼저 해결하고 남은 일정도 갱신합니다.

## 구현할 때 참고

- 김재철: `AuditLogService`·조회 서비스, 통계 조회/확정/보충 서비스·스케줄러. 감사 `MANDATORY`, KST 00:01 확정, 재확정 삭제/삽입, 지역 스냅샷·JDBC 집계를 유지합니다.
- 백한비: `IdempotencyService`, `ReservationStatusHistoryService`, 원장/잔액 경합 테스트.
- 이태호: `SlotReleasedRecorder`, Outbox publisher/relay, 알림 query/consumer·`processed_event`, waitlist 서비스/어댑터·소비 설정.
- Outbox 저장/relay, SlotReleased 수신·중복 처리, Waitlist lost update, 알림 읽음, 통계 확정/재확정 테스트를 실행합니다.
- `MANDATORY`, `REQUIRES_NEW`와 나뉜 Spring 빈을 유지합니다. 외부 HTTP/Kafka 응답을 기다리는 동안 DB 잠금을 붙잡지 않던 기존 구조도 유지합니다.
